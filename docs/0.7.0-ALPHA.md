# Heliolune 0.7.0 alpha evaluation

English · [简体中文](0.7.0-ALPHA.zh-CN.md)

Version `0.7.0-alpha.1` promotes the useful parts of the proposed 0.6.6 and 0.8 roadmap into an auditable experiment: adaptive 1/2/4-worker routing, a shadow decision beside explicit speed-first runs, and `TASK_NODE_V1` execution telemetry. It does not claim that lower parallelism is always faster.

## What shipped

- `start_task` defaults to `adaptive`. Exact low-risk file work selects one owner, bounded moderate work selects owner plus edge/test review, and broad, directory-scoped, high-risk, or reserved-boundary work selects the established four-way plan.
- `profile=speed-first` remains an explicit four-worker control and is still appropriate for independent broad work. `profile=token-first` remains the safety fallback.
- Safe one- and two-worker write plans use the same detached-worktree integration gates as four-way work.
- Speed-first runs record the adaptive route as a non-executing shadow decision.
- Terminal results include versioned task-node timing, routing signals, queue wait, worker sum, critical path, utilization, and Leader share. Metrics not observable at the MCP boundary are explicitly marked unavailable rather than inferred.
- Completed low-risk adaptive one/two-worker work can return directly. High risk, incomplete work, escalation, or unsafe integration still wakes the shared Leader.

## Real matched results

All arms used real GPT-5.6 Luna/max workers on the same checkout. Values are worker-boundary estimates; each arm has one sample.

| Matched task | Control | Adaptive | Wall-time change | Estimated-cost change |
|---|---:|---:|---:|---:|
| Narrow bounded review | 4 workers, 160.253s, 0.588295 | 1 worker, 112.371s, 0.081278 | **-29.88%** | **-86.18%** |
| Moderate bounded review | 4 workers, 254.321s, 0.562255 | 2 workers, 263.399s, 0.354365 | **+3.57%** | **-36.97%** |

The narrow task met the same evidence/risk acceptance shape with far less duplicate work. The two-worker task saved tokens and estimated cost, but one 243.488-second straggler made it slower than the four-worker control. This negative result is retained because it is exactly why the route is an alpha and why explicit speed-first remains available.

An independent eight-audit baseline also showed four-way speed-first at 51.371 seconds versus 163.163 seconds serial, a 3.176x speedup at matched 0.975 quality. Adaptive routing therefore preserves four-way execution for broad independent scope.

## Release gate and limitations

The alpha is acceptable when deterministic tests cover classifier boundaries, 1/2/4 scheduling, direct-versus-Leader reporting, telemetry, safe write isolation, runtime identity, and terminal cleanup; installed-host tests must also prove one start, one await, window closure, runner exit, and app-server exit.

The final gate passed 111/111 tests under Windows PowerShell 5.1 and PowerShell 7.6.4. A fresh installed-host run selected one adaptive worker, completed in 44.463 seconds, emitted `TASK_NODE_V1`, rendered Chinese status, auto-closed the native window, and exited both runner and app-server tree. A separate two-writer real smoke safely applied `alpha.txt` and `beta.txt` from detached worktrees in 62.253 seconds, left the index unstaged, removed temporary worktrees, and exited its runner.

The installed MCP surface measures approximately 1,166 schema tokens; the normal `runtime_info` + `start_task` path is approximately 495 tokens, 3.13% above the retained 0.6.4 measurement of 480. The 15-token increase buys the adaptive profile field and routing description; the advanced batch schema remains approximately 447 tokens.

The live sample count is too small for a universal latency claim. Controller planning and final-acceptance tokens, false acceptance, route regret, duplicate-exploration ratio, and downstream result use are not observable yet. The next evaluation should run repeated randomized matched arms and use the shadow decisions to compare predicted and chosen routes before any stable 0.7 release.
