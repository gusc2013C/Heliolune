# Heliolune 0.8 alpha.3：普通 HelioTerm 直连优化

[English](0.8.0-ALPHA.3-HELIOTERM-DIRECT-OPT.md) · 简体中文

普通 HelioTerm 默认路径已改为确定性直连内核：使用 `execFile` 直接启动已知可执行文件，不经过 shell、不使用 MCP、不创建终端子代理，并在模型边界前压缩输出。结果以 `model=0` 明确证明 HelioTerm 自身没有模型 token。Alpha.3 早期测量使用 Spark/medium 语义回退；最终版本把活动的模型回退绑定到 Luna/high，Spark 名称仅保留为兼容别名。Sol/Luna owner 的模型和推理强度没有变化。

真实 Heliolune 工程匹配测试运行 `tests/pricing.test.mjs` 与 `tests/profiles.test.mjs`，23/23 通过。优化后的 `$helioterm` Desktop 任务使用 62,531 total token、24.721 秒，直连内核仅 271ms、HelioTerm 模型 token 为 0。相较此前模型子代理路径的 172,592 total token、26.450 秒，总 token 降低 63.77%，端到端时间降低 6.54%；内核相对 13.513 秒的旧子任务执行时间降低 97.99%。

首次直连诊断仍重复读取技能、preflight 并遇到一次 WindowsApps shell 失败，共 105,883 token。最终技能取消了普通请求的重复 preflight，默认提示指定系统 PowerShell，根 tool turn 从 4 降到 2，因此又降低 40.94% token。剩余消耗主要是 Desktop 根 Sol 上下文与强制技能读取，不来自 HelioTerm。

额外真实操作也通过：23 测试批量执行 277ms、仓库搜索 37ms、只读 Git 状态 44ms，三者 HelioTerm 模型 token 都为 0；变更型 Git 子命令在启动进程前失败关闭。

## 第二轮：同时优化速度和 token 表面

普通直连路径现在把轻量执行内核与 MCP 传输代码分离，并允许一次进程通过重复 `--request` 承载最多四种观察。兼容测试仍合并为一次 `node --test`；相邻的只读 Git、搜索和进程观察可并行，测试、构建和 benchmark 保持有序屏障。整个批次会先完成协议与命令映射验证，任一非法或变更型操作都会在启动进程前以 `calls=0` 失败。

真实 Heliolune 工程使用“23 项测试 + Git 状态 + 配置搜索”进行 5 轮匹配测试。三次独立直连进程的中位时间为 478.5ms、p95 为 486.5ms；一次批处理的中位时间为 363.6ms、p95 为 368.4ms，分别降低 24.01% 与 24.28%，同时保持 23/23 通过、操作失败为 0、`model=0`。单独 23 项测试的中位时间从 325.7ms 变为 324.2ms，没有单任务速度退化。

同一多观察工作负载交给 owner 的结果轮次从 3 降为 1，降低 66.67%。技能正文从 1,409 降到 1,134 UTF-8 字节（降低 19.52%），单词数从 193 降到 154（降低 20.21%）。这些是直接测得的 token 输入表面；未创建新 Desktop 任务时，不把它外推成未经测量的总 token 数。HelioTerm 子模型 token 仍为 0。
