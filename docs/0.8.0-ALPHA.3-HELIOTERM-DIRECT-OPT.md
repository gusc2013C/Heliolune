# Heliolune 0.8 alpha.3: Ordinary HelioTerm direct execution optimization

English · [简体中文](0.8.0-ALPHA.3-HELIOTERM-DIRECT-OPT.zh-CN.md)

Ordinary HelioTerm now uses a deterministic direct kernel: it starts known executables with `execFile`, does not use a shell or MCP, does not create a terminal child agent, and compresses output before the model boundary. Results include `model=0` to show that ordinary HelioTerm itself used no model tokens. Early alpha.3 measurements used a Spark/medium semantic fallback; the final release binds the active model-backed fallback to Luna/high and retains the Spark name only as a compatibility alias. Sol/Luna owner bindings and reasoning strength are unchanged.

The matched Heliolune engineering run executed `tests/pricing.test.mjs` and `tests/profiles.test.mjs`; all 23/23 tests passed. The optimized `$helioterm` Desktop task used 62,531 total tokens in 24.721 seconds, while the direct kernel took 271ms and HelioTerm model tokens remained 0. Compared with the former model-subagent path (172,592 total tokens and 26.450 seconds), total tokens fell 63.77%, end-to-end time fell 6.54%, and kernel time fell 97.99% versus the former 13.513-second child task.

The first direct diagnostic still reread skills and preflight and hit one WindowsApps shell failure, using 105,883 tokens. The final skill removed repeated preflight for ordinary requests, named the system PowerShell in the default prompt, and reduced root tool turns from four to two, saving a further 40.94%. The remaining cost is primarily Desktop root Sol context and mandatory skill reads, not HelioTerm.

## Second round: speed and token surface

The direct path separates the lightweight execution kernel from MCP transport and allows one process to carry up to four observations through repeated `--request` arguments. Compatibility tests remain one ordered `node --test` barrier; adjacent read-only Git, search, and process observations can run in parallel, while tests, builds, and benchmarks remain ordered. Protocol and command mapping validation runs before any process starts, so an illegal or mutating operation fails with `calls=0`.

Five matched engineering rounds used 23 tests plus Git status and configuration search. Three independent direct runs had a median of 478.5ms and p95 of 486.5ms; one batch had a median of 363.6ms and p95 of 368.4ms, reductions of 24.01% and 24.28%, while retaining 23/23 passing, zero operation failures, and `model=0`. The standalone 23-test median changed from 325.7ms to 324.2ms, with no single-task regression.

The same multi-observation workload now takes one owner result turn instead of three, a 66.67% reduction. The skill body fell from 1,409 to 1,134 UTF-8 bytes (19.52%) and from 193 to 154 words (20.21%). These are directly measured input-surface changes, not an extrapolated total-token claim when no new Desktop task is created. HelioTerm child-model tokens remain 0.
