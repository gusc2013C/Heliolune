# Heliolune 0.7.0-alpha.2 DAG 评估

[English](0.7.0-ALPHA.2.md) · 简体中文

`0.7.0-alpha.2` 实现路线图中任务图与 0.8 调度方向的安全子集，把 alpha.1 仅用于遥测的 task node 升级为可执行 `TASK_DAG_V1`，同时保留启动一次/等待一次、renewable liveness、detached owner、原生窗口关闭和隔离写安全集成。

## 已实现

- 依赖校验、环/缺失节点拒绝，以及确定性的 `pending → ready → running → terminal` 状态转换。
- read/write lease；无序冲突节点在调用模型前失败，read lease 可以重叠。
- 事件驱动 adaptive 宽度 `1 → 2 → 4`。四个独立 READY 节点立即扩到四路；candidate challenge 只在 producer 完成后开启第二槽。
- 按 critical depth、显式 priority、路径/仓库 affinity 和确定性顺序选单。
- 全部 required node 与 `completionQuorum` 完成后，取消尚未开始的 optional node。
- post-patch challenge 绑定 `baseRef + SHA-256 candidateFingerprint`，强制使用不同 worker 槽，读取 producer 的精确 worktree，但不接收 owner reasoning。
- DAG 感知的排队、分配、取消、阻断、lease、宽度、利用率和关键路径遥测。
- 新增显式 `throughput` profile；旧 `speed-first` 保留为别名，token-first 继续作为隔离不安全时的回退。

alpha.2 拒绝链式 writer。当前 detached-worktree 设计不能让后继 writer 安全继承尚未集成的前驱 patch；接受这种图会制造虚假的依赖语义。子任务建议、speculative straggler hedge、Terra 和学习型路由同样延后。

## 真实候选绑定写入运行

最终真实 Luna/max 图在临时 Git 仓库执行 `owner → challenge`：

| 证据 | 结果 |
|---|---:|
| 总墙钟 | 371.676s |
| Owner | `burst-1`，33.383s |
| 宽度变化 | 33.384s，`1 → 2`，`candidate-thread-isolation` |
| Challenge | `burst-2`，337.349s |
| Candidate fingerprint | `3b17d50d…ca55d1f0` |
| 关键路径 | 370.732s |
| Usage | 108,215 input / 104,960 cached / 1,675 output |
| Luna 估算费用 | 0.119005 |

challenge 查看 producer 的精确 post-patch checkout，使用不同 thread/slot，并在完成前保持同一 fingerprint。集成只安全应用 `feature.txt`，index 未暂存，临时 worktree 全部删除，detached runner 退出。337 秒 challenge 是真实延迟成本；DAG 正确不等于任务天然更快。同一图此前一次修正后运行在 174.973 秒完成，challenge 为 140.129 秒，进一步说明这是长尾方差而非稳定延迟估计。

第一次候选运行也完成，但审查发现只有 owner READY 时就于 0ms 扩宽，并把 challenge kind 报成 `inspect`。两个遥测缺陷均修复并增加回归，随后从头重跑得到上面的最终结果。

最终发布前审查又发现一个调度边界：若 producer 完成时 sibling 仍占用备用槽，challenge 可能复用刚空闲的 producer 槽。现在 candidate node 会把 producer 槽视为绝对不可选并等待另一槽。同一轮审查还让 throughput 运行时与声明的 1/2/4/8 schema 对齐，并从 candidate 依赖输入中删除 producer summary/evidence，只保留完成状态和 fingerprint 元数据。新增聚焦回归后，完整发布套件为 121 项全部通过。

另一项当前构建 throughput 回归让两个不相交 writer 并行运行，并在 63.067 秒完成。两个节点均完成，`alpha.txt` 与 `beta.txt` 安全集成，主 index 未暂存，只剩 fixture 的主 worktree，detached runner 已退出。该结果保留独立 writer 路径，同时继续有意拒绝链式 writer。

使用最终 cachebuster 重装后，全新 Codex app-server host smoke 在 64.771 秒完成。`runtime_info` 返回精确 alpha.2 version/build/prompt 与 `TASK_DAG_V1` 能力；真实 adaptive worker 完成、独立 await 返回终态、简体中文原生窗口自动关闭，detached runner/app-server 进程树退出。

## Adaptive 与 throughput 匹配对照

同一四节点 renewable-liveness 审计分别运行一次：

| 路线 | 墙钟 | 最慢节点 | Worker 总时长 | Leader | 估算费用 |
|---|---:|---:|---:|---:|---:|
| Adaptive DAG | 338.958s | 317.408s | 939.217s | 20.976s | 1.010623 |
| Throughput | 465.561s | 437.035s | 1,172.280s | 27.951s | 0.802499 |
| Adaptive 观察差值 | **-27.19%** | **-27.37%** | **-19.88%** | **-24.95%** | **+25.93%** |

两条路线都在 0ms 开放四槽，node 分配顺序相同。因此 adaptive 观察到的更短墙钟和更高费用不能归因于 DAG 调度，只能主要视为 `n=1` 的 Luna 长尾/输出方差。更窄且有证据支持的结论是：四个独立节点就绪时，确定性 READY/lease/affinity 检查没有产生可见启动延迟。本版本不作 p50/p95 或普适加速声明。

## Tool schema 成本

安装态四工具面约为 1,478 schema token。常规 `runtime_info + start_task` 路径约 505 token，相对保留的 0.6.4 基线 480 增加 5.2%。高级 `start_batch` schema 约 749 token，相对原 447 增加 67.6%，因为现在声明依赖、lease、affinity、priority、optional node 与 quorum。该成本只位于高级工具面，也不能解释为模型运行速度收益。
