# Heliolune 0.6.2 前端应用 benchmark

[English](0.6.2-FRONTEND-APPLICATION-BENCHMARK.md) · 简体中文

本次只测试一个 Sol+Luna 方案：由 Sol controller 定义产品契约并最终验收，Heliolune 的四路 Luna/max 将 Vinext starter 替换为响应式 AI 任务与费用运营面板 **Tokenary**，Luna/high Leader 负责跟踪健康状态与压缩结果。没有运行 Sol-only 对照，也没有部署到外部。

## 结果

原始任务没有做到无人干预完成。owner 在 300.130 秒后等待 app-server 完成通知超时，但已经生成一个 40,384 字节、修改四个允许文件的补丁。Heliolune 0.6.2 按安全策略拒绝合并失败 writer 的补丁，因此原任务以 `partial` 结束且没有自动应用文件。随后使用 Heliolune 现有的 clean-head、scope、重叠检测和 `git apply --check` 门禁，确定性恢复了这份原始 Luna 补丁。恢复结果单独计算，不能把原任务包装成成功。

| 指标 | 结果 |
|---|---:|
| Heliolune job | `5c82928b-c947-404d-ba14-966e4abb4f03` |
| 原始任务状态 | Partial；未自动集成 |
| 任务墙钟时间 | 321.804 秒 |
| 最慢 worker | 300.130 秒 |
| Luna 用量 | 输入 142,257 / 输出 7,121；缓存 105,472 |
| Luna 缓存率 | 74.14% |
| Luna worker 实测费用 | 0.450291 单位 |
| 历史 benchmark 校准的 Sol-only 预测 | 1.847435 单位 |
| 方向性预测节省 | 1.397144 单位 / 75.63% |
| 同 token 套用 Sol 价格 | 11.257275 单位；仅作价格敏感性分析，不作为节省估算 |

恢复后的站点可在 Windows 下直接通过生产构建，不再依赖 POSIX 环境变量赋值。浏览器分别按 1440 和 390 CSS 像素验收，没有控制台错误或横向溢出；搜索、状态筛选、暂停/恢复、深浅主题以及主题/筛选偏好持久化均正常。页面包含费用、预计节省、模型占比、完成任务吞吐、工作状态与近期活动，桌面和手机端视觉体系一致。

该产物尚未达到发布标准。starter 自带测试仍强制要求旧 skeleton 存在，因此产品替换后 0/2 失败。这里也有 Sol 规格错误：验收要求 `npm test` 通过，但硬写入范围没有包含 `tests/`。三路 Luna 审查都发现了这个矛盾，现有流程却不能暂停 writer 并向 Sol 请求一个极短决策。旧 `_sites-preview` 目录仍残留，ESLint 有一处 effect 内同步更新 state 的错误，手机端许多控件只有 26–32 CSS 像素，触控面积偏小。

## 验收评分

| 维度 | 证据 | 得分 |
|---|---|---:|
| 产品与视觉 | 有辨识度的仪表盘、真实感数据、桌面/手机信息层级清楚 | 8.5/10 |
| 客户端交互 | 浏览器实测搜索、筛选、任务切换、toast、主题和偏好持久化 | 8.0/10 |
| 响应式与可访问性 | 无溢出，有语义标签、focus/reduced-motion CSS；触控目标偏小 | 6.5/10 |
| 工程完整度 | 生产构建通过；旧测试失败、lint 一处错误、starter 文件残留 | 5.0/10 |
| 自主编排 | 补丁有实际价值，但原任务没有自动集成 | 3.0/10 |

**应用价值结论：** Heliolune 0.6.2 已经适合作为低成本、Sol 深度监督下的实现草稿生成器。Luna 仅用 0.450291 费用单位就产出了可信的中型前端补丁，并且并行审查准确发现了上层契约错误。但它还不能可靠地无人干预承担一个中型前端功能：完成通知超时、缺少调度前契约检查、全有或全无的集成策略仍会迫使 controller 介入。

后续版本应在调度前检查 acceptance 与写入 scope 是否一致；只有 reviewer 发现真实契约矛盾时才暂停并向 Sol 请求一次极短决策；区分“writer 仍有活动”和“完成通知丢失”；对非空超时补丁提供经过 build、lint、test、scope 门禁的隔离恢复流程。中型前端任务还需要自适应文件预算，避免把整个产品挤进一个高密度页面模块。
