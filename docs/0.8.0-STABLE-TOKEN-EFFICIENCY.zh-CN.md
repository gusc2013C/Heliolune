# Heliolune 0.8.0：稳定版 token-efficiency 边界

[English](0.8.0-STABLE-TOKEN-EFFICIENCY.md) · 简体中文

构建身份：`0.8.0+codex.20260818153255`

Heliolune 0.8.0 在测量 Sol controller、零模型 terminal 路径与发布验证后，将 Native V2 提升为稳定版。机器可读证据见 [`benchmarks/results/0.8.0-stable-token-efficiency.json`](../benchmarks/results/0.8.0-stable-token-efficiency.json)。

## 实测结论

- 观测到的长 Sol 任务记录 71,502,261 个输入 token，其中 70,178,816 命中缓存（98.15%）。剩余热点是任务过长、9 个用户轮次内 615 次采样，以及 468 个 wrapper 中 405 个单调用（86.54%）。这些是 rollout 诊断计数，不是供应商计费。
- HelioTerm 处理 1,485,884 字节并返回 833,431 个紧凑字节，节省 652,453 字节（43.9%）。bytes/4 方法估算净节省 163,065 个内容 token，并记录 80 个被避免的唤醒/模型边界；该估算不是计费数据。
- 成功的完整发布 validator 暴露 18,538 字节；`-Compact` 仍执行全部 205 项测试，但只暴露 65 字节，实测减少 18,473 字节（99.65%）。失败时保留最后 40 行，最多 8 KiB。
- 持久化 Native V2 元数据证明已验收工程 owner 为 `gpt-5.6-luna`、`max` effort；两个有界轮次共 9 次工具调用，单结果最大 7,025 字节，累计工具输出 18,146 字节。

## 稳定版策略

- Sol 批量执行互不重复的验收检查，不重跑 `verification.owner`，并优先采用紧凑 HelioTerm evidence。
- 发布打包自动调用紧凑验证。
- 纯版本号与发布说明传播由 Sol 持有；Luna owner 只用于能从缓存实现上下文获益的有界工程与修复。
- Alpha.3/alpha.4 历史测量保持不变。本版本不会把诊断计数包装成 billing 声明，也不宣称前瞻控制已经节省过去的 Sol 输入。

## 验证

紧凑 validator 已在 PowerShell 7 与 Windows PowerShell 5.1 下通过完整套件。另用 1,000 行合成失败验证了非零退出与有界诊断尾部。
