Alpha.4 records bounded-discovery and routing evidence without turning rollout diagnostics into a billing claim. The machine-readable companion is [`benchmarks/results/0.8.0-alpha.4-token-efficiency.json`](../benchmarks/results/0.8.0-alpha.4-token-efficiency.json).

## The 1..4 readFirst gate

The Heliolune Native V2 context pack now makes the discovery budget explicit:

- `context.anchors` are searched once across every `context.readFirst` path before any file is read.
- `context.readFirst` contains 1..4 paths. The anchor-first query consumes one of the five initial repository calls; the remaining calls are bounded slices.
- The owner reads only those paths and files directly required by facts found in them. It does not perform repository enumeration or full-file rereads.
- This gate keeps implementation context compact while retaining the exact evidence needed for a scoped change.

A fresh no-change alpha.4 owner proof ran under the compliant policy with `gpt-5.6-luna/max`, 4 tool calls, 6,977-byte maximum persisted tool output, 10,461-byte cumulative persisted tool output, and 102,468 total diagnostic tokens. The proof passed Native V2 identity and the 24 KiB per-tool/192 KiB cumulative limits. These are current-policy proof facts, not retrospective implementation savings.

## Enforceable owner output budgets

Alpha.4 now enforces read/search evidence at 12 KiB (12288 bytes) and 160 lines, every tool result at 24 KiB (24576 bytes), cumulative owner tool output at 192 KiB (196608 bytes), and compact verification output. These are forward-looking controls; the retained diagnostic counters above do not claim retrospective savings.

## Aggregate rollout counters

The retained seven prior Luna/max owner runs total 2,752,349 diagnostic tokens: 2,670,303 input, 2,290,688 cached input, 82,046 output, and 50,589 reasoning output, with 59 tool calls and 624,332 bytes of tool output. Two avoidable sessions account for 364,015 diagnostic tokens, or 13.23%.

These are aggregate rollout counters, not billing tokens. The JSON stores no prompts, command payloads, environment or stdin data, secrets, task identifiers, or raw tool output.

## Single-Luna repair comparison

The measured previous repair used two turns and 4,347,302 diagnostic tokens. The current single-Luna repair used one turn and 3,724,754 diagnostic tokens: 622,548 fewer, a 14.32% reduction. This is a matched rollout comparison, not a universal cost or quality guarantee.

## HelioTerm A/B routing

The ordinary-failure classifier now treats the 8.8 KB single-input and 15.0 KB batch-input failures as deterministic observations: the old classifier routed both to Luna, while alpha.4 routes them with `model=0` and `semanticScore=0`. Explicit semantic requests and real test diagnostics remain routed to Luna with `semanticScore=3`.

The audit records only these aggregate sizes, route labels, model mode, and semantic scores. It does not retain the underlying payload or output.

## Measurement boundary

The release note reports diagnostic evidence supplied by the rollout. It does not claim that the alpha.4 read policy reduced the current owner proof, does not reprice diagnostic counters as provider billing, and does not expose private execution material.
