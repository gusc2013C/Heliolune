# Heliolune 0.8 alpha.3: Three-path HelioTerm measurements

English · [简体中文](0.8.0-ALPHA.3-HELIOTERM-AB3.zh-CN.md)

On 2026-08-08, the same code snapshot, Spark model (medium), command, and 23-test suite compared an ordinary terminal, direct HelioTerm, and MCP HelioTerm. All three successful paths had the same quality and passed 23/23 tests.

In controlled independent Spark sessions, the ordinary terminal used 31,350 total tokens, direct HelioTerm used 31,925 (+1.83%), and minimal MCP used 38,619 (+20.97% versus direct). MCP compressed 2,060 bytes of raw output to 41 bytes, reducing model-visible output 98.01%, uncached input 23.18%, and wall time 26.18%; delayed tool discovery added cached tool context, so total tokens increased instead.

In real Desktop orchestration, the root task used directly consumed 61,825 total tokens in 12.057 seconds; the root task plus direct HelioTerm used 172,592 total tokens in 26.450 seconds, increases of 179.16% and 119.37%. The current Desktop Native V2 child agent did not receive a local `helioterm.run` MCP tool; the failure sample fell back to an ordinary terminal and failed. The role now reports `FAIL|calls=0|mcp-unavailable` when the tool is invisible and forbids fallback.

Therefore alpha.3 keeps HelioTerm as an independently usable component included by default. Ordinary terminal work uses the direct `model=0` path and does not create a child task; a Luna/high model-backed HelioTerm leaf is reserved for explicitly requested semantic terminal work. MCP remains experimental rather than the default path. Complete machine evidence is in the independent HelioTerm repository at `benchmarks/results/0.1.0-alpha.1-ab3.json`.
