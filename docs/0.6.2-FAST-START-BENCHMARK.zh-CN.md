# Heliolune 0.6.2 快速启动基准

[English](0.6.2-FAST-START-BENCHMARK.md) · 简体中文

这个低 token、确定性 benchmark 从同一个 Git 基线修复 `mergeMaintenanceWindows`。公开测试 4 项，独立 evaluator 另含 8 项隐藏 contract 与不可变性用例；两组方案均达到 12/12。

| 方案 | 正确性 | 墙钟时间 | 模型用量 | 模型估算费用 |
|---|---:|---:|---:|---:|
| Sol-only Codex task | 12/12 | 123.532s | Sol 输入 120,374 / 输出 4,469；缓存 96,768 | 7.512100 |
| Heliolune 0.6.2 engine | 12/12 | 127.451s | Luna 输入 126,833 / 输出 5,290；缓存 74,496 | 0.457633 |

Heliolune 墙钟慢 3.17%（`0.969x`），worker 侧模型费用低 93.91%。该费用比例不是端到端 Codex task 节省：Heliolune 组由发布 harness 驱动，没有计费的 Sol controller turn。MCP 的历史校准投影为 1.877557 Sol-only 单位、方向性节省 75.6261%。要测量缩短后的 Sol controller 前缀，仍需在安装后新建 task 完成一次端到端测量。

默认 `start_task` 启动 4 路工作流。mutating owner 在 109.723 秒完成；边界与正确性审查完成，contract 审查诚实返回 partial。确定性集成只应用 `src/merge-windows.mjs`，公开与隐藏测试全部通过。只读伴随审查 partial/超时不会再无条件阻止已完成 writer。

启动开销按序列化字符数除以四估算。热路径 skill 从约 3,173 token 降至 1,096（−65.5%）；默认安装态 pool 工具面从约 1,586 降至 1,192 token，常规 `start_task` schema 单独约 455 token。skill 与默认 pool schema 合计减少约 51.9%，不含未变化的独立 await schema。

0.6.1 的 Heliolune task 被排除：其 task-local 工具注册表没有暴露插件 MCP，随后 Sol 扫描缓存目录并手工启动了短生命周期 server。它测量的是 host/setup 失败，而非 Heliolune 执行。0.6.2 在两个必需工具任一缺失时会立即失败。
