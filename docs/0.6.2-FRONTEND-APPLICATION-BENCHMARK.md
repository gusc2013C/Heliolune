# Heliolune 0.6.2 frontend application benchmark

English · [简体中文](0.6.2-FRONTEND-APPLICATION-BENCHMARK.zh-CN.md)

This single-arm benchmark asked one Sol controller plus Heliolune's four-way Luna pool to replace a Vinext starter with **Tokenary**, a responsive AI task-and-cost operations dashboard. Sol defined the product contract and performed final acceptance; Luna/max owned implementation while Luna/high supervised worker health and compressed the result. There was no Sol-only arm and no external deployment.

## Result

The run did **not** complete as a hands-off application workflow. The owner produced a 40,384-byte patch touching four allowed files, but timed out waiting for the app-server completion notification after 300.130 seconds. Heliolune 0.6.2 correctly refused to merge a patch from a failed writer, so the original job ended `partial` with no files applied. A later deterministic recovery used Heliolune's existing clean-head, scope, overlap, and `git apply --check` integration gates to apply that exact Luna artifact. Recovery is reported separately and does not turn the original run into a success.

The recovered site production-builds successfully on Windows without POSIX environment assignments. Browser acceptance at 1440 CSS pixels and 390 CSS pixels found no console errors and no horizontal overflow. Search, status filters, pause/resume, light/dark theme, and persisted theme/filter preferences worked. The dashboard includes spend, projected savings, model mix, completed-task throughput, work status, and recent activity with a coherent responsive visual system.

The artifact is not release-ready. The inherited tests still assert that the starter skeleton must exist and therefore fail 0/2 after the product replacement. This was partly a Sol contract error: acceptance required `npm test` to pass while the hard write scope omitted `tests/`. All three Luna review streams identified the contradiction, but the current workflow could not pause the writer for a compact Sol decision. The obsolete `_sites-preview` directory remains, ESLint reports one synchronous state update inside an effect, and many mobile controls measure only 26–32 CSS pixels rather than a touch-friendly target.

| Autonomous orchestration | Useful patch survived, but the original job did not integrate it | 3.0/10 |

**Practical conclusion:** Heliolune 0.6.2 already has application value as a low-cost, Sol-supervised implementation draft generator. Luna produced a credible medium-sized frontend patch for 0.450291 price units, and the parallel reviewers caught the governing contract defect. It is not yet reliable enough to own a medium frontend feature hands-off: the completion-notification failure, missing preflight escalation, and all-or-nothing integration still require controller intervention.

The next release should validate acceptance against write scope before dispatch, pause for Sol only when a reviewer finds a true contract contradiction, distinguish an active writer from a missing completion notification, and offer a bounded quarantine/recovery path for a non-empty timed-out patch after deterministic build, lint, test, and scope gates. Medium frontend work also needs a larger or adaptive file budget instead of forcing the product into one dense page module.
