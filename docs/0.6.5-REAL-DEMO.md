# 0.6.5 real-demo validation

English · [简体中文](0.6.5-REAL-DEMO.zh-CN.md)

## Release gate

The 0.6.5 candidate was not accepted after a single happy-path run. Testing began with the installed 0.6.4 plugin and continued in a fix-and-restart loop until the final code passed the automated suite and every supported real-demo lane below. A failed run never counted as evidence of success.

The initial installed 0.6.4 four-way demo ran for about 5 minutes 48 seconds before the process owning the job exited. Later candidates exposed a normal-completion app-server leak, an intermittent detached-runner exit, partial claim visibility, a POSIX shutdown gap, stale same-version MCP processes, silent workers with indefinitely renewable leases, and Windows status/terminal-record races. During the final audit, job `993ad283` completed but its benchmark deleted the temporary job root before the panel read the terminal snapshot; the user-visible panel therefore remained on its last running frame. That exact panel was closed, the benchmark was made headless, and the production panel now also fails closed when its record disappears.

The final `0.6.5-owner-heartbeat-r2` implementation requires exact pool/request/await build identity, writes an independent five-second owner heartbeat, fails a 30-second stale owner, interrupts four consecutive app-server-silent checks, publishes claims atomically, confirms app-server exit after Windows process-tree termination, tolerates transient terminal replacements, and forces every terminal or unrecoverable window state into the 15-second close path.

This matrix covers default and maximum read concurrency, queue reuse, token-first fallback, isolated writes, exact same-version runtime rejection, independent terminal delivery, owner and worker stall convergence, visible Windows status, missing-record closure, long-running ownership, and resource cleanup. It does not prove that all future repositories, model outputs, host versions, or external failures are defect-free; it establishes that no remaining usage-level defect was observed across the supported release scenarios exercised here.
