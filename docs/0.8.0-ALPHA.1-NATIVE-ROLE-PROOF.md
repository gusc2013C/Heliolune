# Heliolune 0.8.0 alpha.1: Native V2 role proof

The P0 role-routing smoke passed on 2026-08-08 with Codex Desktop `26.803.5235.0` and kernel `0.147.0-alpha.6.5`.

| Route | Actual role | Actual model / effort | Backend | Result |
| --- | --- | --- | --- | --- |
| Sol → owner | `heliolune_luna_owner` | `gpt-5.6-luna` / `max` | V2 | Pass |
| Luna → peer | `heliolune_luna_peer` | `gpt-5.6-luna` / `max` | V2 | Pass |
| Luna → terminal | `heliolune_spark_terminal` | `gpt-5.3-codex-spark` / `medium` | V2 | Pass |

Every spawn used `fork_turns="none"` and omitted explicit model and reasoning overrides. Persisted rollouts confirmed the role, actual model, effort, and V2 backend, ruling out Terra fallback and task-name-only false positives.

The role-proof inspector can also enforce a non-negative maximum for persisted `custom_tool_call` response items with `--expect-max-tool-calls`.

It can fail closed against the latest persisted `total_token_usage.total_tokens` with `--expect-max-total-tokens`.

It can also fail closed against the final persisted `total_token_usage.reasoning_output_tokens` with `--expect-max-reasoning-tokens`. When supplied, the final value must be present, a non-negative safe integer, and no greater than the expected maximum.

It can also fail closed against the final persisted `total_token_usage.output_tokens` with `--expect-max-output-tokens`. When supplied, the final value must be present, a non-negative safe integer, and no greater than the expected maximum.

Role configuration is loaded when a Codex task starts. A task that predated `.codex/config.toml` returned `unknown agent_type 'heliolune_luna_owner'`, while a fresh task routed successfully. Installing or changing roles therefore requires a new task.

Clean child history does not eliminate fixed system, plugin, skill, and tool context. The minimal owner marker consumed 17,860 total tokens; the peer consumed 17,736 and Spark consumed 16,562. After one owner follow-up and several lifecycle calls, cumulative owner input reached 128,776 tokens, of which 107,008 were cached. Heliolune should reuse persistent children and batch terminal work instead of spawning per command.

An installed-skill forward test also exposed duplicate root/owner preflight execution and broad directory output. Alpha.1 now passes compact preflight evidence in the contract and explicitly forbids the owner from rerunning preflight or dumping whole directories.

A forced one-file delegation isolated another source of waste: shell-launch and quoting retries. Generic Windows guidance still produced four repository tool calls and 125,467 cumulative tokens. The final owner role now uses a deterministic system `cmd.exe` + `type` template for one-file reads. Persisted rollout `019fdfe0-9c7e-7a70-9070-981efe878bf6` proved exactly one repository tool call, the real Luna/max/V2 role, no edits, and 57,484 cumulative tokens: 54.2% below the four-call run and 57.6% below the earlier five-call run. This tiny task was intentionally forced through Luna; normal routing keeps trivial one-file work in Sol because the remaining fixed Desktop context dominates.

See the machine-readable [`0.8.0-alpha.1-native-role-proof-r1.json`](../benchmarks/results/0.8.0-alpha.1-native-role-proof-r1.json). The next stage is a matched real-engineering alpha.2 benchmark with one Luna writer and no Spark.
