## Owner tool-output budget

Alpha.4 现在强制 read/search 证据上限为 12 KiB (12288 bytes)/160 行、每个 tool result 上限为 24 KiB (24576 bytes)、owner tool output 累计上限为 192 KiB (196608 bytes)，并保持紧凑的 verification 输出。这些是向前生效的控制，不对保留的诊断 counter 声称追溯节省。

Heliolune Native V2 context pack 将发现预算固定为：

- 在读取任何文件前，先对全部 `context.readFirst` 路径执行一次 `context.anchors` 定向搜索。
- `context.readFirst` 只能有 1..4 个路径。anchor-first 查询消耗五个初始仓库调用中的一个，其余调用使用有界切片。
- owner 只读取这些路径以及由其中事实直接要求的文件，不做仓库枚举，也不重新读取完整文件。
- 这个 gate 保持实现上下文紧凑，同时保留有界变更所需的精确证据。

A fresh no-change alpha.4 owner proof 在合规 policy 下运行：`gpt-5.6-luna/max`、4 次 tool call、最大持久化 tool output 6,977 bytes、累计 10,461 bytes、总诊断 token 102,468。该 proof 通过 Native V2 身份以及 24 KiB 单工具/192 KiB 累计限制。这些是当前 policy 的 proof 事实，不是追溯性的 implementation savings。

## 聚合 rollout counter

之前七次 Luna/max owner run 合计 2,752,349 个诊断 token：input 2,670,303、cached input 2,290,688、output 82,046、reasoning 50,589，59 次 tool call 和 624,332 字节 tool output。两个可避免 session 合计 364,015 个诊断 token，占 13.23%。

这些是聚合 rollout counter，不是 billing token。JSON 不保存 prompt、命令载荷、环境或 stdin 数据、secret、task identifier 或 raw tool output。

## single-Luna repair 对比

之前的 repair 使用两轮、4,347,302 个诊断 token；当前 single-Luna repair 使用一轮、3,724,754 个诊断 token，减少 622,548，降幅 14.32%。这是匹配的 rollout 对比，不是普遍成本或质量保证。

## HelioTerm A/B 路由

普通失败分类器现在把 8.8 KB 单输入和 15.0 KB 批量输入失败视为确定性观察：旧分类器会把两者路由到 Luna，而 alpha.4 使用 `model=0` 和 `semanticScore=0`。显式语义请求和真实测试诊断仍路由到 Luna，`semanticScore=3`。

audit 只记录这些聚合大小、路由标签、model mode 和 semantic score，不保留底层 payload 或输出。

## 测量边界

本说明只报告 rollout 提供的诊断证据，不声称 alpha.4 read policy 降低了当前 owner proof，不把诊断 counter 按 provider 价格重新计费，也不暴露私有执行材料。
