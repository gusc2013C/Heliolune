# 0.8.0 alpha.3：Luna 默认执行与有界会话复用

[English](0.8.0-ALPHA.3-LUNA-SESSION-REUSE.md) · 简体中文

## 当前策略

- 普通 HelioTerm 命令继续走确定性 direct runner，模型消耗为 `model=0`。
- 只有显式需要语义 terminal 时才创建模型角色；HelioTerm 与 HelioTerm MCP 均绑定 `gpt-5.6-luna/high`。
- 旧 `spark_terminal` 名称仅保留兼容性，其真实绑定也已改为 Luna/high；Spark 不再是活动绑定。
- 工程 owner、peer、critic 继续使用 Luna/max，没有为了省 token 降低推理强度。
- 同一个 Luna owner 在 contractId、目标、scope、保留决策、branch 和 worktree 不变时最多复用 3 轮：实现、聚焦修复、证据恢复。任一边界变化都必须创建新 owner。
- 模型 HelioTerm 在同一父任务中最多复用 8 个请求；每请求最多 4 次工具调用，request/response 分别限制为 64/256 UTF-8 bytes。

## 为什么这样定

当前官方 Codex 费率表中，Sol 的 input / cached input / output 为 125 / 12.5 / 750，Luna 为 5 / 0.5 / 30。三类计费都恰好是 25:1，因此在需要模型执行 terminal 工作时，Luna 是明确的默认选择。无需模型判断的命令仍应 direct 执行，因为零模型调用比任何便宜模型都更省、更快。

一次真实 Native V2 Luna owner 连续会话中，首轮 cached input 为 0；复用后的累计 input 为 128,776、cached input 为 107,008，累计 cache rate 为 83.10%。这证明同 session 复用可以命中稳定前缀，但不代表每个项目都能获得同样比例。因此实现采用 3 轮硬上限，并要求后续轮只能提交同 contract 的 `HELIOLUNE_OWNER_FOLLOWUP_V1`，避免缓存收益被无限增长的历史上下文抵消。

## 不能放宽的验收边界

复用只减少重复发现和启动开销，不把 Luna 的自报结果当成验收。Sol 仍独立检查实际改动路径、diff 与 acceptance checks；持久化 rollout 仍必须证明模型、effort、Native V2、父子关系、工具预算和无回退。若模型实际回退到 Terra、Spark 或其他绑定，proof 必须失败。
